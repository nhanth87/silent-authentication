# 3GPP TS 33.501 — 5G security (N32 / SEPP) — silent-auth & SMS-protection edge

Reference notes for the **5G** security edge. Two roles in this project:

1. **5G silent-auth path** — a 5G device's silent auth is asserted via NEF/NRF to the UDM
   (Nudm) and AUSF (Nausf) rather than MAP/S6a (see the CAMARA NV note).
2. **Strategy B** — the 5G SMS/interconnect firewall rides **SEPP/N32** (FS.36).

- **Spec:** 3GPP TS 33.501 (Security architecture and procedures for 5G System)

---

## 1. 5G silent-auth surface (vs 2G/3G/4G)

| Access | Resolver | Verifier |
|--------|----------|----------|
| 2G/3G | PGW/GGSN binding | MAP PSI/ATI/SAI (TS 29.002) |
| 4G/LTE | PGW (S6b/SGi) | S6a ULR/AIR (TS 29.272) |
| **5G** | SMF/UPF (N4/N3 accounting, exposable via NEF) | **Nudm/Nausf** via NEF/NRF |

The "IP→MSISDN" binding in 5G still sits in the data plane (SMF/UPF/NEF), never in the identity
plane — the same two-stage Resolver→Verifier split holds.

---

## 2. N32 / SEPP (interconnect boundary)

SEPP terminates **N32** between PLMNs; a Security Edge Protection Proxy applies the roam/
interconnect policy (FS.36). For silent auth this is the *outer* boundary: it must not block the
operator-internal NEF/UDM lookups, but must filter cross-PLMN signalling (including 5G SMS over
SMSF/`Nsms`).

---

## 3. Security mapping

- **Own UDM/AUSF only** — operator-internal Nudm; SEPP blocks foreign control-plane probes.
- **Fail-closed** — no Nudm/Nausf confirmation ⇒ FALLBACK.
- **Replay** — bind NepF context to `ts`+`reqId` (same window rule as MAP/Diameter).

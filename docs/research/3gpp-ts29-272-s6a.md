# 3GPP TS 29.272 — Diameter S6a/S6d (MME/SGSN ↔ HSS) for Silent Auth

Reference notes for the **Diameter** leg of the silent-authentication stack (LTE/EPC). S6a/S6d
gives the SAS Verifier an HSS-side view of attachment, serving node, and EPS authentication
vectors. Extracted 2026-08-19 from the normative spec.

- **Spec:** 3GPP TS 29.272 V19.5.0 (2026-03)
- **Title:** Evolved Packet System (EPS); Mobility Management Entity (MME) and Serving GPRS
  Support Node (SGSN) related interfaces based on Diameter protocol
- **Source artefact:** `https://www.3gpp.org/ftp/Specs/archive/29_series/29.272/29272-j50.zip`
  (contains `29272-j50.docx`). Not committed — re-fetch for normative text.

---

## 1. Scope & application identifiers

S6a/S6d is a **Diameter application** (not SS7): message transport is Diameter over SCTP/TCP,
commands use a shared `Command-Code` space allocated by IANA (RFC 5516).

| Interface | Peers | Application-Id |
|-----------|-------|----------------|
| **S6a** | MME ↔ HSS | `16777251` |
| **S6d** | SGSN ↔ HSS | `16777251` |
| S13/S13' | ME identity check (EIR) | `16777252` |

```asn.1
< Update-Location-Request > ::= < Diameter Header: 316, REQ, PXY, 16777251 >
< Authentication-Information-Request > ::= < Diameter Header: 318, REQ, PXY, 16777251 >
```

This is the LTE/EPC counterpart of the 2G/3G MAP operations in
[`3gpp-ts29-002-map.md`](3gpp-ts29-002-map.md). Where MAP speaks PSI/ATI/SAI over TCAP,
S6a speaks ULR/AIR with the HSS directly.

## 2. Command reference (clause 7.2, Command-Code values)

| Command | Code | Direction | Purpose | Silent-auth relevance |
|---------|------|-----------|---------|------------------------|
| **ULR / ULA** | 316 | MME/SGSN → HSS | Register location, pull subscription | Attachment liveness; HSS learns serving MME |
| **CLR / CLA** | 317 | HSS → MME/SGSN | Cancel location | Detects a *new* serving node ⇒ active takeover |
| **AIR / AIA** | 318 | MME/SGSN → HSS | Fetch EPS auth vectors | **SIM-swap / credential freshness (LTE)** |
| **IDR / IDA** | 319 | HSS → MME/SGSN | Push subscription data | Subscription change → re-score |
| **DSR / DSA** | 320 | HSS → MME/SGSN | Delete subscription data | Provisioning / de-provisioning |
| **PUR / PUA** | 321 | MME/SGSN → HSS | Purge UE (no longer here) | "Purged" ⇒ **not reachable** |
| **RSR / RSA** | 322 | HSS → MME/SGSN | Reset after HSS restart | Fault recovery (not a swap) |
| **NOR / NOA** | 323 | MME/SGSN → HSS | Notify (e.g. IMS voice, PDN-GW) | Serving-node / service changes |

The "R" bit in `Command Flags` distinguishes request vs answer on the same code.

## 3. AIR/AIA — spec fact, **not** on the verify path

`Authentication-Information-Request/Answer` (AIR/AIA, code 318) is the S6a equivalent of MAP
`sendAuthenticationInfo`: the MME/SGSN asks the HSS for EPS authentication vectors. The answer
carries `Authentication-Info` = `E-UTRAN-Vector { RAND, XRES, AUTN, KASME }` (plus the
`Item-Number` / `Synchronization-Failure` handling for re-sync).

**The SAS does not use AIR/AIA for SIM swap.** AIR consumes a real EPS vector set and advances the
AuC SQN (MAC-failure re-sync risk on the live USIM). 4G/5G freshness instead comes from a
**read-only Sh UDR/SNR** (TS 29.328/29.329) read of the current MSISDN↔IMSI binding age — the
same "last-seen change age" logic as MAP SAI, without minting vectors.

## 4. Correction — S6a is **not** the Wi-Fi path

The project framing "Diameter S6a (cho Wi-Fi)" is imprecise. S6a/S6d is **EPS/EPC** — it
requires a cellular attachment (MME/SGSN) and therefore **mobile data**, not Wi-Fi-only.

| Path | Root of trust | Needs cellular data? |
|------|---------------|----------------------|
| IP-match (Resolver + Verifier) | PGW IP↔MSISDN + MAP/Diameter | **Yes** |
| **S6a/S6d** (this spec) | HSS state & EPS vectors (LTE) | **Yes** (LTE attach) |
| **TS.43 EAP-AKA (Wi-Fi)** | SIM credential via EAP-AKA | **No** (Wi-Fi + browser) |

Wi-Fi silent auth rides **EAP-AKA** (GSMA **TS.43** Service Entitlement Configuration /
3GPP TS 33.402 SWm/SWx through the 3GPP AAA), **not** S6a. Keep this as an open item until
the Wi-Fi entitlement server path is confirmed (see `../design/` open items).

## 5. Security mapping (must not regress — see design checklist)

- **Own HSS only** — same fail-closed rule as MAP: no Diameter interconnect probing; trust
  only own-HSS responses (FS.19 edge/DEA).
- **Fail-closed** — missing EPS vectors, `PUR`/purged state, or no ULR evidence ⇒ FALLBACK.
- **One dialog per stage** — bound the Diameter transaction; time out and abort (S6a budget
  2 s per the design table).
- **Replay / race** — `Session-Id` + timestamps; treat any HSS state as point-in-time.
- **Privacy** — IMSI/EPS vectors stay on bank backend / SAS; app receives a boolean only.
